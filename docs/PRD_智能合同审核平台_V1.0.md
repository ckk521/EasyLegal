## 1. 产品概述

### 1.1 价值主张

**一句话定位**：为律所律师提供智能合同生成与审核服务，通过AI + 人工协同，将合同处理时间从小时级缩短到分钟级，提升工作效率与服务质量。

**核心价值**：
- **效率提升**：智能体自动收集需求、生成合同、审核风险，减少80%重复性工作
- **质量保障**：AI辅助风险识别，降低法律风险，提升合同质量
- **服务升级**：快速响应客户需求，提升客户满意度与粘性

### 1.2 成功指标

**用户指标**（MVP目标）：
- DAU：50人（单个律所试点）
- 30天留存率：≥60%
- 功能使用率：≥80%的用户每周使用≥3次

**效率指标**（MVP目标）：
- 合同生成时间：≤15分钟（从需求到初稿）
- 合同审核时间：≤5分钟（从上传到报告）
- 人工干预率：≤20%（AI可独立完成的任务比例）

**质量指标**（MVP目标）：
- 风险识别准确率：≥85%
- 修改建议采纳率：≥70%
- 用户满意度：≥4.5/5.0

**商业指标**（MVP目标）：
- 付费转化率：试点律所转付费≥50%
- ARPU：≥5000元/月/律所
- 客户LTV：≥6个月

### 1.3 MVP版本范围

**MVP版本核心功能**：
- C端：智能体对话（法律咨询、委婉拒绝非法律问题）
- B端：规则上传管理（合同模板、审核规则、案例上传）
- 智能体：基于B端上传的规则服务C端用户

**MVP版本不包含**（后续迭代）：
- 合同审核工作流
- 合同修正工作流
- 法务部门工作流操作
- B端智能体对话

### 1.4 后续版本规划

**V1.x版本**：
- 法务部门接入合同审核工作流
- 法务部门接入合同修正工作流
- B端智能体对话功能

**V2.0版本**：
- 多租户管理
- 复杂权限控制
- 电子签名集成
- 企业微信/钉钉集成

### 2.4 核心业务场景（MVP版本）

#### 场景1：合同生成

**用户旅程**：
```
用户描述需求 → 智能体提问 → 用户回答 → 生成合同 → 用户确认 → 导出文档
```

**详细流程**：
1. 用户通过聊天界面描述合同需求（如"我需要一份房屋租赁合同"）
2. 智能体识别意图，调用合同生成流程
3. 智能体根据合同类型，逐项提问收集必要信息（出租方、承租方、租赁标的等）
4. 用户回答问题
5. 智能体调用合同模板，填充信息，生成合同初稿（含AI润色）
6. 用户预览合同，可进行修改或直接导出

**成功标准**：
- 从需求到初稿时间 ≤15分钟
- 信息收集准确率 ≥90%
- 用户满意度 ≥4.0

#### 场景2：法律咨询

**用户旅程**：
```
用户提问 → 智能体判断 → RAG检索 → 返回答案
```

**详细流程**：
1. 用户提问（如"违约责任怎么约定"）
2. 智能体判断是否属于法律范畴
3. 非法律问题委婉拒绝，引导回法律范畴
4. 法律问题通过RAG检索知识库
5. 返回答案（条款解释、案例参考）

**成功标准**：
- 响应时间 ≤3秒
- 答案准确率 ≥90%
- 用户满意度 ≥4.0

#### 3.2.11 B端配置项完整清单（核心）

> **设计原则**：C端智能体的所有行为都依赖B端的配置。B端配置与智能体深度打通，运营人员可自由调整Agent策略，无需修改代码。

| 配置分类 | 配置项 | 格式/说明 | 默认值 |
|----------|--------|-----------|--------|
| **大模型配置** | API KEY | 字符串 | - |
| | BASE URL | 字符串 | - |
| | MODEL NAME | 字符串 | - |
| **Embedding配置** | 模型选择 | m3e-base（本地） | m3e-base |
| | Chunk大小 | 整数（字符数） | 512 |
| | Overlap | 整数（字符数） | 50 |
| **核心意图配置** | 意图定义文档 | .md格式（见附录） | 预置模板 |
| **合同模板** | 模板文件 | PDF/Word/md/text | - |
| | 字段定义 | JSON格式 | 预置租赁合同字段 |
| **法律范围配置** | 法律问题判断规则 | .md格式 | 预置规则 |
| **拒绝话术配置** | 非法律问题拒绝文案 | 文本 | "我主要专注于法律和合同相关的问题..." |
| **敏感信息配置** | 敏感信息类型 | 身份证号/银行卡/地址 | - |

## 4. 非功能性需求

### 4.1 性能要求

| 指标 | 要求 | 说明 |
|------|------|------|
| 合同解析时间 | ≤30秒 | 10页合同（含OCR） |
| 合同生成时间 | ≤2分钟 | 含AI润色 |
| 审核时间 | ≤5分钟 | 从上传到报告 |
| 响应时间 | ≤3秒 | 普通查询 |
| 并发用户数 | 50 | MVP规模，后续大规模需优化 |
| 系统可用性 | ≥99% | MVP阶段 |

**说明**：MVP阶段暂不考虑高并发，后续大规模铺开时需做性能优化和数据库迁移。

### 4.1.1 会话与Token管理

| 配置项 | 设置 | 说明 |
|--------|------|------|
| Token有效期 | 7天 | JWT token过期时间 |
| 会话过期 | 不过期 | 用户会话长期有效 |
| 多设备登录 | 允许 | 同一账号可多设备同时登录 |

### 4.1.2 网络异常处理

| 场景 | 处理方式 |
|------|----------|
| SSE连接断开 | 客户端自动重连（浏览器原生支持） |
| 重连成功后 | 从服务端拉取最近对话历史，显示在界面 |
| 用户发送消息时断网 | 提示"网络异常，请检查网络后重试"，消息保留在输入框 |
| 服务端响应中断 | 显示已接收的部分内容，提示"响应中断，请重新提问" |

**技术实现**：
- 前端监听 SSE `onerror` 事件，显示"连接中断，正在重连..."
- 重连后调用 `GET /chat/history?session_id=xxx` 获取最近消息
- 输入框内容保存在 localStorage，断网不丢失

### 6.4 核心意图文档格式规范

```markdown
# 意图名称：合同生成

## 触发词
- 生成合同
- 制作合同
- 起草合同
- 我要签合同

## 意图描述
用户需要生成一份新的合同，Agent应引导用户填写必要的合同字段。

## 后续动作
调用合同生成接口，根据合同类型引导用户逐项填写必填字段。

## 示例对话
用户：我要租房子，帮我写一份合同
Agent：好的，我来帮您生成一份租赁合同。请问出租方是谁？

## 触发词

- 这个条款什么意思

## 意图描述
用户咨询法律相关问题，需要从知识库中检索答案。

## 后续动作
RAG检索知识库，返回相关条款解释、案例参考或法律法规。

## 示例对话
用户：违约责任怎么约定？

- 合同进度

用户查询已创建合同的状态或内容。

## 后续动作

## 示例对话
用户：我之前那份租赁合同怎么样了？
Agent：您是指和【张三】签订的租赁合同吗？目前状态是"待确认"...
```

## 7. 决策记录

### 7.0 核心设计原则

> **核心原则**：C端智能体与B端配置深度打通
>
> - 智能体的所有行为（意图识别、知识检索、话术输出）都依赖B端配置
> - B端运营人员可自由调整Agent策略，无需修改代码
> - 配置变更实时生效，支持快速迭代

**配置驱动架构**：
```
B端配置中心 → 配置存储 → Agent运行时
     ↑                          ↓
     └──── 配置生效反馈 ←───────┘
```

### 7.1 技术选型

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 后端框架 | Python + FastAPI | 开发快速，AI集成友好 |
| AI框架 | LangChain Agent | 成熟的LLM应用框架 |
| 数据库 | SQLite | 本地存储，轻量级，MVP阶段简单够用 |
| 前端框架 | React + Ant Design | 企业级UI组件库 |
| 部署方式 | Docker + Docker Compose | 本地部署，易于管理 |
| 前端部署 | 打包到后端 | FastAPI托管静态文件，部署简单 |
| 对话接口 | SSE (Server-Sent Events) | 单向推送，实现简单，适合流式响应 |
| 向量数据库 | Chroma | 本地存储，轻量级 |
| Embedding模型 | m3e-base | 国产中文模型，免费本地部署 |
| 大模型配置 | B端配置入口 | 支持配置API KEY、BASE URL、MODEL NAME |
